# تمرین ۱ — Agent استنتاج محلی

برنامه یک مسئله را می‌خواند، با مدل محلی `qwen3.8:27b` در Ollama دو برنامهٔ Python مستقل می‌سازد، هر برنامه را روی همین سیستم اجرا می‌کند، و اگر خروجی‌ها یکی باشند همان خط را به‌عنوان پاسخ نهایی می‌نویسد. اگر اختلاف داشته باشند، یک فراخوانی سوم برنامه را اصلاح می‌کند. زنجیرهٔ استدلال وارد فایل خروجی نمی‌شود.

## نصب

1. [Ollama](https://ollama.com) را نصب کنید و سرویس آن را روشن بگذارید.
2. مدل ارزیابی را بگیرید:

```bash
ollama pull qwen3.8:27b
```

3. وابستگی جداگانه‌ای لازم نیست. `requirements.txt` خالی از پکیج است؛ برنامه فقط کتابخانهٔ استاندارد Python 3 و سرور محلی Ollama را استفاده می‌کند.

## اجرا

```bash
python main.py --input input.json --output output.json
```

ورودی:

```json
{
  "id": "test_001",
  "problem": "متن مسئله"
}
```

خروجی:

```json
{
  "id": "test_001",
  "answer": "FINAL_ANSWER"
}
```

فیلد `answer` فقط پاسخ نهایی است. نام مدل را می‌توان با متغیر محیطی `OLLAMA_MODEL` یا آرگومان `--model` عوض کرد. پیش‌فرض `qwen3.8:27b` است.

## معماری

هر مسئله حداکثر پنج فراخوانی مدل دارد.

1. **Solver A** مسئله را به یک برنامهٔ Python (جست‌وجوی کامل، حساب دقیق، یا BFS) ترجمه می‌کند. برنامه در یک فرایند جدا با محدودیت زمان اجرا می‌شود و باید دقیقاً یک خط چاپ کند.
2. اگر اجرا خطا بدهد، همان تلاش یک‌بار با متن خطا اصلاح می‌شود.
3. **Solver B** مستقل از اول، دوباره برنامه می‌نویسد.
4. اگر دو خروجی برابر باشند، همان پاسخ نوشته می‌شود.
5. اگر برابر نباشند، **Adjudicator** با دیدن هر دو پاسخ یک برنامهٔ اصلاح‌شده می‌نویسد و خروجی اجرای آن پذیرفته می‌شود.

مدل به API ابری وصل نمی‌شود. فکر خام مدل (`think`) خاموش است تا خروجی قابل پارس و زمان اجرا کوتاه‌تر بماند. ارقام فارسی و عربی داخل متن مسئله قبل از حل به رقم ASCII تبدیل می‌شوند تا خطاهای عددی کمتر شود.
